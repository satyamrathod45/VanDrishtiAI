## 1. Executive Summary & Architecture Overview

VanDrishti AI is designed to transform unstructured camera-trap imagery from field SD cards into verified individual-tiger intelligence. The database architecture is built upon a **Unified Dual-Layer Design**:

1. **Vector Similarity Store Layer**: Stores 2048-dimensional normalized feature embeddings generated by `tiger_reid.onnx` from cropped tiger flank photos, supporting sub-millisecond visual pattern matching ($O(N)$ flat cosine dot-product search).
2. **Relational & Spatial Metadata Layer**: Stores camera trap stations, GPS coordinates, timestamps, tiger profiles, verification audit logs, and movement alerts.

## 2. Core Entities & Schema Specifications

The system consists of **4 core interconnected models**:

```
┌──────────────────────┐              ┌──────────────────────────────────┐
│       CAMERAS        │ 1          N │   TIGER_EMBEDDINGS (Sightings)   │
│──────────────────────│─────────────▶│──────────────────────────────────│
│ PK  camera_id        │  captures    │ PK  id                           │
│     name, zone       │              │ FK  tiger_id ────────────────┐   │
│     gps, status      │              │ FK  camera_id                │   │
└──────────────────────┘              │     crop_path, source_image  │   │
                                      │     gps, timestamp           │   │
                                      │     vector (2048-d Float32)  │   │
                                      │     reid_confidence, status  │   │
                                      └────────────────▲─────────────┼───┘
                                                       │ 1           │
                                     triggers evidence │             │
                                                       │ N           │ N
                                      ┌────────────────┴────────┐    │
                                      │         ALERTS          │    ▼ 1
                                      │─────────────────────────│ ┌──────────────────────┐
                                      │ PK  alert_id            │ │        TIGERS        │
                                      │ FK  tiger_id ───────────┼─┤──────────────────────│
                                      │ FK  sighting_id         │ │ PK  tiger_id         │
```

### Model 1: `tigers` (Master Identity Catalogue)
Represents individual resident tigers monitored within the reserve.

| Field Name | Type | Constraints | Data Origin / Source | Purpose & Downstream Impact |
| :--- | :--- | :--- | :--- | :--- |
| **`tiger_id`** | `TEXT` | `PRIMARY KEY` | Forest Dept ID (e.g. `"TGR-024"`) | Canonical system-wide identifier. |
| **`display_name`** | `TEXT` | `NOT NULL` | Forest Reserve Catalogue (e.g. `"T-024 · Moharli Male"`) | Human-readable label for officers. |
| **`sex`** | `TEXT` | `Male` / `Female` / `Unknown` | Forest Dept record or Officer input | Used for territory size & breeding analysis. |
| **`age_class`** | `TEXT` | `Cub` / `Sub-adult` / `Adult` / `Old` | Officer input during registration | Population demographic tracking. |
| **`status`** | `TEXT` | `active` / `missing` / `deceased` | Officer administrative status | Filters active population in UI. |
| **`primary_zone`** | `TEXT` | `NOT NULL` | Auto-calculated (dominant camera zone) | Home territory baseline for movement alerts. |
| **`profile_image`** | `TEXT` | Path string | Best clear flank crop (`/crops/...`) | Avatar thumbnail on UI cards and profile page. |
| **`distinctive_marks`** | `TEXT` | Nullable | Officer field notes | Manual visual cross-checking guide. |
| **`total_sightings`** | `INTEGER` | `DEFAULT 0` | Auto-incremented counter | Fast display on cards without scanning all sightings. |
| **`first_seen`** | `DATETIME` | `NOT NULL` | Sighting timestamp of earliest photo | Lifespan and tracking duration. |
| **`last_seen`** | `DATETIME` | `NOT NULL` | Sighting timestamp of newest photo | Computes days-since-last-seen & absence alerts. |

| **`source_image`** | `TEXT` | `NOT NULL` | SD Card filename (`IMG_001_0337.jpg`) | Full raw context image for officer inspection. |
| **`camera_id`** | `TEXT` | `FOREIGN KEY (cameras.camera_id)` | Camera trap hardware ID | Station attribution and camera health. |
| **`station_name`** | `TEXT` | `NOT NULL` | Camera station registry | Readable location name (`"Teliya Buffer Lake"`). |
| **`zone`** | `TEXT` | `Core` / `Buffer` / `Corridor` | Camera station metadata | Reserve zonation boundary. |
| **`gps`** | `JSON / Object` | `{ "lat": REAL, "lng": REAL }` | Station GPS coordinates | Coordinates for Leaflet map & trajectory lines. |
| **`timestamp`** | `DATETIME` | `NOT NULL` | Image EXIF date/time | Chronological sorting of tiger movement paths. |
| **`reid_confidence`** | `REAL` | `0.0 to 100.0` | Cosine Similarity Score | Match confidence percentage. |
| **`review_status`** | `TEXT` | `verified` / `pending_review` / `rejected` | Review workflow state | Separates confirmed vs audited sightings. |
| **`verified_by`** | `TEXT` | Nullable | Officer ID (`"FO-1024"`) | Audit trail of human verification. |
| **`vector`** | `BLOB / Float32Array` | `2048 floats (8,192 bytes)` | Output of `tiger_reid.onnx` | Dense feature vector for visual similarity search. |

### Model 4: `alerts` (Movement & Spatial Intelligence)
Automated alerts generated when tiger movement deviates from historical baselines.

| Field Name | Type | Constraints | Data Origin / Source | Purpose & Downstream Impact |
| :--- | :--- | :--- | :--- | :--- |
| **`alert_id`** | `TEXT` | `PRIMARY KEY` | Auto-generated (`"ALT-2026-084"`) | Unique alert identifier. |
| **`tiger_id`** | `TEXT` | `FOREIGN KEY (tigers.tiger_id)` | Linked Tiger | Identifies which tiger caused the alert. |
| **`sighting_id`** | `TEXT` | `FOREIGN KEY (tiger_embeddings.id)` | Sighting trigger | Direct link to the evidence crop photo. |
| **`alert_type`** | `TEXT` | Enum (see below) | Spatial Rule Engine | Categorizes anomaly type. |
| **`severity`** | `TEXT` | `critical` / `high` / `medium` / `info` | Rule Engine Severity Matrix | UI badge color and priority. |
| **`title`** | `TEXT` | `NOT NULL` | Template generator | Short headline (`"Territory Shift Detected"`). |
| **`description`** | `TEXT` | `NOT NULL` | Narrative generator | Explanation (`"T-024 detected 14 km outside usual range"`). |
| **`evidence_crop_path`** | `TEXT` | Path string | `tiger_embeddings.crop_path` | Instant image preview in Alerts panel. |
| **`timestamp`** | `DATETIME` | `NOT NULL` | Sighting timestamp | Time of occurrence. |
| **`is_resolved`** | `BOOLEAN` | `DEFAULT 0` | Officer action | Toggle to mark alert as reviewed/resolved. |

#### Alert Types & Trigger Conditions:
1. **`territory_shift`**: A tiger is detected $>10\text{ km}$ away from its dominant `primary_zone`.
2. **`corridor_crossing` / `buffer_breach`**: A tiger is detected near human-settlement buffer zones (human-wildlife conflict risk).
3. **`long_absence`**: A resident tiger has not been photographed anywhere in the reserve for $>45\text{ days}$.
4. **`unknown_cluster`**: Multiple photos of an uncatalogued tiger captured across adjacent cameras.

## 3. Vector Database & Similarity Search Specifications

### 1. Vector Dimension & Normalization
- **Feature Extractor:** `models/tiger_reid.onnx`
- **Input Tensor:** Float32 array of shape `[1, 3, 128, 256]` (Letterboxed RGB, $256\times128$ px)
- **Output Tensor:** Float32 array of shape `[1, 2048]`
- **L2 Vector Normalization:**
  $$\hat{\vec{v}} = \frac{\vec{v}}{\|\vec{v}\|_2} = \frac{\vec{v}}{\sqrt{\sum_{i=1}^{2048} v_i^2}}$$

### 2. Search Algorithm: Flat Cosine Dot-Product
Because vectors are strictly unit-normalized ($\|\hat{\vec{u}}\|_2 = 1, \|\hat{\vec{v}}\|_2 = 1$), the cosine similarity is computed directly by the inner dot-product:
$$\text{Similarity}(\hat{\vec{u}}, \hat{\vec{v}}) = \sum_{i=1}^{2048} \hat{u}_i \cdot \hat{v}_i$$

### 3. Latency & Scale
- **Storage size per vector:** $2048 \times 4\text{ bytes} = 8\text{ KB}$ (8,192 bytes).
- **Scale:** 5,000 tiger observations = **40 MB total memory**.
- **Search speed:** Single flat JavaScript / WASM scan over 5,000 vectors takes **$< 1.5\text{ milliseconds}$**.

### 4. Automated Decision Boundaries:

```
│   │                                                         │
```

## 4. Query Patterns & Common API Operations

### 1. Vector Search Query
```javascript
// Input: Query vector extracted from new crop
// Output: Top-K matching sightings and their stored tiger IDs
const results = vectorDb.searchByVector(queryVector, { topK: 5 });
```

### 2. Sighting History & Movement Trail (For GIS Leaflet Map)
```javascript
// Fetch all GPS points for Tiger T-024 in chronological order
const trajectory = vectorDb
  .filter(sighting => sighting.tiger_id === "TGR-024")
  .sort((a, b) => new Date(a.timestamp) - new Date(b.timestamp))
  .map(s => ({
    lat: s.gps.lat,
    lng: s.gps.lng,
    station: s.station_name,
    time: s.timestamp,
    cropUrl: s.crop_path
  }));
```

### 3. Station Sighting Analysis (For Camera Health)
```javascript
// Fetch all tigers captured at a specific camera station
const stationSightings = vectorDb.filter(s => s.camera_id === "PTR_BUFF_ST06");
```

## 5. SQL Schema Definition

```sql
-- 1. Tiger Master Catalogue
CREATE TABLE tigers (
    tiger_id TEXT PRIMARY KEY,
    display_name TEXT NOT NULL,
    sex TEXT CHECK(sex IN ('Male', 'Female', 'Unknown')) DEFAULT 'Unknown',
    age_class TEXT CHECK(age_class IN ('Cub', 'Sub-adult', 'Adult', 'Old')) DEFAULT 'Adult',
    status TEXT CHECK(status IN ('active', 'missing', 'deceased')) DEFAULT 'active',
    primary_zone TEXT NOT NULL,
    profile_image TEXT,
    distinctive_marks TEXT,
    total_sightings INTEGER DEFAULT 0,
    first_seen DATETIME NOT NULL,
    last_seen DATETIME NOT NULL,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- 2. Camera Stations
CREATE TABLE cameras (
    camera_id TEXT PRIMARY KEY,
    name TEXT NOT NULL,
    zone TEXT CHECK(zone IN ('Core', 'Buffer', 'Corridor')) NOT NULL,
    range TEXT NOT NULL,
    latitude REAL NOT NULL,
    longitude REAL NOT NULL,
    status TEXT CHECK(status IN ('active', 'maintenance', 'inactive')) DEFAULT 'active',
    last_active DATETIME NOT NULL,
    total_photos INTEGER DEFAULT 0
);

-- 3. Tiger Flank Embeddings & Sightings (Vector DB Layer)
CREATE TABLE tiger_embeddings (
    id TEXT PRIMARY KEY,
    tiger_id TEXT NOT NULL,
    crop_path TEXT NOT NULL,
    source_image TEXT NOT NULL,
    camera_id TEXT NOT NULL,
    station_name TEXT NOT NULL,
    zone TEXT NOT NULL,
    latitude REAL NOT NULL,
    longitude REAL NOT NULL,
    timestamp DATETIME NOT NULL,
    reid_confidence REAL NOT NULL,
    review_status TEXT CHECK(review_status IN ('verified', 'pending_review', 'rejected')) DEFAULT 'pending_review',
    verified_by TEXT,
    vector BLOB NOT NULL, -- 2048-dim Float32Array (8192 bytes)
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (tiger_id) REFERENCES tigers(tiger_id) ON DELETE CASCADE,
    FOREIGN KEY (camera_id) REFERENCES cameras(camera_id)
);

-- 4. Spatial & Movement Alerts
CREATE TABLE alerts (
    alert_id TEXT PRIMARY KEY,
    tiger_id TEXT NOT NULL,
    sighting_id TEXT NOT NULL,
    alert_type TEXT CHECK(alert_type IN ('territory_shift', 'corridor_crossing', 'long_absence', 'unknown_cluster')) NOT NULL,
    severity TEXT CHECK(severity IN ('critical', 'high', 'medium', 'info')) NOT NULL,
    title TEXT NOT NULL,
    description TEXT NOT NULL,
    evidence_crop_path TEXT NOT NULL,
    timestamp DATETIME NOT NULL,
    is_resolved BOOLEAN DEFAULT 0,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (tiger_id) REFERENCES tigers(tiger_id) ON DELETE CASCADE,
    FOREIGN KEY (sighting_id) REFERENCES tiger_embeddings(id) ON DELETE CASCADE
);

-- Indices for rapid indexing & query performance
CREATE INDEX idx_embeddings_tiger_id ON tiger_embeddings(tiger_id);
CREATE INDEX idx_embeddings_camera_id ON tiger_embeddings(camera_id);
CREATE INDEX idx_embeddings_timestamp ON tiger_embeddings(timestamp);
CREATE INDEX idx_alerts_tiger_id ON alerts(tiger_id);
CREATE INDEX idx_alerts_resolved ON alerts(is_resolved);
```
